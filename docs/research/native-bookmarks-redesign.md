# 原生书签增强版改造方案

日期：2026-10-26。状态：产品方向和第一阶段实施已获确认；第一阶段已完成本地开发与自动化验收，旧书签直接导入已追加实现，常规编辑仍未实施。

本次交付为现有书签工作区的改造方案与低保真交互草图，不是已实现的页面。用户已确认：以浏览器原生书签为唯一书签数据源，展示和维护同一份数据，使用浏览器自身的同步能力。

**产品目标与成功标准**

面向研究、开发、写作等过程中频繁访问收藏内容的 Chromium 用户。最重要的任务是快速找到并打开书签，其次是保存和整理。新标签页高频使用，界面不应要求用户重新学习一套分类体系。

- 在 BrowseLoom 新增、编辑、移动或删除的内容，能在浏览器书签管理器中核对；反向操作也能反映到 BrowseLoom。
- 新用户授权后直接看到已有书签，无需导入、注册或建立新的收藏库。
- 文件夹层级、条目顺序、同名书签及合法的重复 URL 都能被保留。
- 原生书签卸载插件后仍保留；旧插件数据在卸载时可能被浏览器清除，因此迁移和备份入口必须明确说明。
- 同步由浏览器账户与设置决定。产品显示保存位置，不能把“写入成功”宣传成“其他设备同步完成”。

**现状依据**

| 当前实现 | 改造影响 |
| --- | --- |
| `extension/services/storage-service.js` 中 `bookmarkLibrary` 为独立本地模型 | 退出日常书签写入路径，作为旧数据保留 |
| `extension/services/bookmarks-service.js` 中 `importBrowserTree()` 复制原生树并平铺深层目录 | 新版直接读取原生树，不执行这一导入流程 |
| `extension/index.html` 中分类导航、主内容、最近/热门两列 | 收敛为文件夹导航与主内容两个区域 |
| `extension/bookmarks.js` 中备注、自定义图标、布局和导入权限文案 | 精简编辑器，替换权限引导与设置 |
| `extension/background.js` 中 `bookmark-current-page` 打开带草稿的新标签页 | 保留草稿入口，最终保存改为原生书签 |
| `extension/app.js` 的 `deferred` 与 `savedSessions` 等独立能力 | 本次不迁移，也不混入原生书签 |
| `PRIVACY.md` 承诺仅在导入时读取、不修改原生书签 | 新版开放维护能力前同步修订 |

**首版范围**

| 能力 | 决策 |
| --- | --- |
| 原生文件夹树、多层导航、面包屑 | 实现 |
| 全部书签搜索，标题/URL 匹配与路径定位 | 实现；检索在本地完成 |
| 网格/列表切换 | 保留；默认网格，复用现有视觉变量 |
| 新建/编辑书签、新建/重命名文件夹、移动与删除 | 实现；包含多选移动、删除 |
| 手动顺序、拖动排序 | 实现；写回原生顺序 |
| 按名称/添加时间查看 | 实现为临时展示排序，不写回原生顺序 |
| 多选打开、文件夹批量打开 | 实现，显示本次将打开的条目数 |
| 收藏当前页快捷键 | 保留，保存前可选原生文件夹 |
| 默认文件夹、视图、密度 | 本地展示偏好 |
| 旧插件书签迁移、备份、迁移结果核对 | 实现 |
| 最近/热门两列、备注编辑、标签、自定义图标、每个文件夹不同卡片尺寸 | 首版移出新界面；已有值保留在旧数据备份 |
| 侧边栏新增书签面板、标签页批量收藏、文件夹打开为标签组 | 后续迭代，不并入本次改造 |
| AI 分类、自动去重、失效链接检测、全文收藏、自建同步 | 不在本方案范围 |

**视觉方向**

用户在桌面浏览器中反复打开新标签页，在浅色或深色系统环境下快速查找资料。沿用现有主题选择与 `--ink`、`--font-sans`、`--content-card-surface` 等变量，保持克制配色、清晰焦点和可读内容表面；不新增另一套主题或装饰性背景。

参考 Chrome 书签管理器的文件夹语义、Bookmark Sidebar 的树导航、现有 BrowseLoom 的网格/列表语言。仅借鉴结构，不宣称复刻或完成竞品实测。正文采用现有字体；书签 favicon 是辅助识别信息，加载失败使用本地字母/通用图标。

图中账户/此设备分组仅在浏览器提供可区分的数据时出现，不能强造两个分组。根节点类型与数量动态读取，不通过名称或固定 ID 猜测。未知同步信息显示“浏览器书签”，不显示“已同步”。

- 桌面目录区建议约 240px；内容区伸缩。取消默认活动侧栏，将可用宽度留给名称与内容。
- 点击文件夹进入，树展开按钮只展开。当前位置、展开状态与键盘焦点分别表达。
- 原生名称原样展示：空标题用“未命名书签”作为界面占位，不回写改名；长标题截断但提供完整文本。
- 搜索默认跨全部可见原生书签，结果使用紧凑列表，显示完整路径和“所在文件夹”入口；清空搜索返回此前位置。
- 文件夹也可以匹配搜索，类型清楚标识。搜索结果禁止拖动排序；同 URL 的不同书签分别显示。
- 单击书签默认新标签页打开；提供“当前标签页打开”菜单，保留中键及修饰键惯例。
- 设置中可将当前位置设为默认文件夹；失效时回退到根目录概览，不自动创建替代文件夹。
- 目录根概览列出浏览器提供的根文件夹。首次授权先进入根概览，避免擅自选择账户或本地保存区域。
- 窄窗口约 720px 以下，目录收起为“文件夹”按钮，内容保留面包屑；编辑表单占满可用宽度。适配 390px 窗口不等于承诺移动 Chrome 可运行该扩展。

**页面草图：新增、编辑与移动**

```text
点击“新增书签”或触发收藏当前页快捷键
                 ↓
┌──────────────────────────────────────┐
│ 新增书签                       关闭  │
│ 名称  [Chrome 扩展文档             ] │
│ 网址  [https://developer.chrome…   ] │
│ 保存到  账户书签 / 书签栏 / 工作     │
│         [选择文件夹]                │
│ 修改会保存到浏览器书签。             │
│                        [保存书签]   │
└──────────────────────────────────────┘
                 ↓
 API 成功 → 更新页面与目录 → “已保存到‘工作’”
 API 失败 → 保留填写内容 → 就地显示原因与重试

多选条目 → [移动 3 项] → 目录选择器 → [移动到“开发文档”]
```

- 复用已有编辑弹窗，不新增复杂抽屉系统。名称、网址、保存位置是全部主要字段；文件夹编辑只有名称和位置。
- 普通新建默认当前可写文件夹；搜索/根概览中新增、快捷键捕获时，使用上次明确选择且仍有效的目标，否则要求选择。保存前始终展示完整路径。
- 查到相同 URL 时提示其已有位置，但不禁止再次收藏、不自动覆盖。提供跳转查看入口。
- 默认手动顺序严格对应原生 `index`，不强行“文件夹在前”。临时排序时关闭排序拖拽并说明如何切回。
- 同层拖动改变顺序；拖到目录目标执行移动。提供键盘可操作的“移动到”菜单及手动模式下“上移/下移”，拖拽不是唯一操作方式。
- 文件夹不能移动到自身或后代。特殊根目录、受管理条目的修改行为依据 API 能力禁用并解释原因。
- 跨账户/本地区域移动前提示“保存区域将改变，可能影响其他设备是否可见”；失败时保留原位置和选择，不用复制加删除强行替代。
- 批量打开默认仅当前层书签；“包含子文件夹”需明确选择。超过 10 个时确认实际数量；逐项报告打开失败，不显示笼统成功。
- 批量操作中选择父文件夹及其子项时先消除重复操作目标。部分成功时列出成功/失败数量，保留失败项选择供处理。

**删除规则**

单项与批量删除均有明确确认。删除文件夹文案：“删除‘工作’及其中的 18 个书签、3 个子文件夹？这会修改浏览器书签；若参与同步，其他设备也可能受到影响。”主按钮写“删除文件夹及内容”。

首版不提供跨会话回收站，不沿用旧库整体快照撤销，也不暗示 Chrome 原生撤销一定能恢复扩展操作。用户想保留内容时应先移动内容再删除空文件夹。正式删除前重新读取目标与数量；数量变化时更新确认，失败后重读实际结果。浏览器 API 没有事务性批量删除，确认到执行之间仍可能发生其他来源变更，不能承诺绝对原子性。

**权限与关键状态**

| 状态 | 页面行为 |
| --- | --- |
| 未授权 | “连接浏览器书签”说明与按钮；不展示伪空书签库 |
| 首次连接 | “直接显示和管理浏览器书签。这里的修改也会反映到浏览器中。”点击后申请可选权限 |
| 旧版已授权 | 首次进入展示使用方式变化说明，点击“启用原生书签管理”后开放写操作；此前仅预览 |
| 拒绝授权 | 保留连接按钮与返回标签页入口，不反复弹权限请求 |
| 读取中 | 有布局的骨架状态，不短暂显示“没有书签” |
| 空文件夹 | “此文件夹还没有书签”，提供新增书签、新建文件夹 |
| 搜索无结果 | 展示当前关键词与清除搜索，不自动发送到外部搜索引擎 |
| 读取失败 | “暂时无法读取浏览器书签”，提供重试，不把失败数据写回 |
| 权限被撤销 | 清除内存中的可见书签内容，停用写操作，回到连接状态 |
| 当前目录被外部删除 | 返回最近仍存在的祖先或根概览，说明目录已删除 |
| 编辑期间内容被外部改变 | 提醒用户重新核对当前内容，保留未提交输入，不静默覆盖 |
| 大批量导入或同步事件 | 合并刷新，保留滚动与展开状态，结束后重读核对 |
| 受管理书签 | 可浏览；不可写操作明确禁用并说明“由组织管理” |

升级后的应用内说明是对旧版“只读”承诺的变更告知，不是重复请求已经授予的浏览器权限。其确认只影响用户何时启用新版管理功能。

完整支持键盘导航、可见焦点、编辑关闭后焦点返回、状态播报、减少动态效果偏好。中英文文案同步维护；现有商店 `__MSG_...__`、`default_locale` 与 `en`/`zh_CN` 打包检查继续保留。

**旧数据迁移：预览后复制，保留原件**

新版不再提供“从 Chrome 导入到插件”功能。只有检测到非空旧 `bookmarkLibrary` 时才出现迁移提示，可稍后处理。旧库冻结为只读，供查看、导出和迁移，不继续承担日常收藏功能。

```text
发现旧插件书签
    ↓
[可选：导出旧书签备份] → 下载包含备注/图标/顺序等信息的版本化 JSON
    ↓
选择迁移目标（一个可写原生文件夹）
    ↓
预览：新增候选 / 已有相同内容 / 需核对 / 不支持的地址
    ↓
用户勾选要复制的条目，确认新增的目录结构与数量
    ↓
在目标下创建“BrowseLoom 旧书签”文件夹并逐项复制
    ↓
结果：已复制 / 已存在 / 待核对 / 失败 → 定位原生文件夹
```

迁移规则：

1. 按用户 2026-10-27 确认，直接导入不以导出为前置条件。导出仅为可选备份，导入始终保留本地旧库。
2. 分类映射为迁移根下的普通文件夹，旧文件夹映射为其子文件夹，分类中的直接书签放入分类文件夹。保留当前旧模型可表达的顺序；过去导入时已丢失的原生深层路径不能反推出。
3. 原生书签完全不被自动移动、重命名或删除。迁移仅创建用户确认的新目录和条目，不合并同名目录。
4. 在当前浏览器范围内先读取现有树。旧导入 ID 可作为辅助线索，但必须核对对应节点仍存在及标题/URL 内容，不能仅凭 ID 决定覆盖或跳过。
5. 标题与 URL 完全相同的条目标记“已有相同内容”，展示现有路径，默认不勾选，允许用户明确复制一份。相同 URL 但名称不同、同名但 URL 不同、旧来源失效的条目列为需核对；不得以去重名义丢弃。
6. 不删除 URL 的 query/hash，不进行宽松 URL 归一化合并。旧库内部的重复条目也分别列出，由用户决定。
7. 备注、自定义颜色/图标、统计和卡片尺寸不写入原生名称或 URL，仅保留在旧库与 JSON；预览明确列出不能迁移的字段和涉及数量。
8. 在本地保存迁移批次、源条目 ID、目标 ID 与执行结果。暂停、失败、关闭后恢复时重新核对目标，禁止直接重跑全部复制。若 API 成功但记录尚未写入就中断，恢复时将可能匹配的新条目标为待核对，不能宣称能自动做到严格一次执行。
9. 迁移进行期间只允许一个写入执行者，避免多标签页重复启动；复用可用的后台消息处理入口，不引入同步框架或新依赖。
10. 不做自动整体回滚：用户或浏览器可能已修改新条目。提供迁移根定位和清晰结果供用户检查。重试只处理用户确认的失败/待核对项。
11. 迁移完成不自动删除旧库。旧库清理作为后续独立入口，在用户已备份并确认后处理；首版只保留和导出。

**技术落地方案**

在现有原生 JavaScript、Manifest V3 与服务组织方式中调整，不新增框架、后端、云存储或依赖。

| 层 | 职责 |
| --- | --- |
| `bookmarks-service.js` | 封装 `getTree/getChildren/search/create/update/move/remove/removeTree`，返回原生 ID 与父子结构；集中校验和错误归类 |
| `bookmarks.js` | 页面状态、树导航、搜索、编辑、多选、权限与事件响应；维护可重建的内存索引 |
| `index.html`、`bookmarks.css` | 目录树/面包屑/工具栏、编辑器精简、状态与响应式布局 |
| `storage-service.js` | 保存版本化展示偏好、旧库与迁移记录；禁止日常书签内容回写 `bookmarkLibrary` |
| `background.js` | 保留快捷键草稿捕获；承接迁移互斥及写入任务，适应 service worker 中断后恢复 |
| README、PRIVACY、商店说明与测试 | 替换独立库/只读导入承诺，验证中英文与发布包 |

原生数据是唯一事实来源；内存树和搜索索引可随时重建，不构成第二套可编辑书签库。首版偏好只保存在当前配置文件，不承诺布局跨设备同步。旧库、备份和迁移日志属于历史保护数据，不参与原生日常编辑。

初始化先建立事件监听再读取快照；读取期间的变化标脏并补一次刷新，避免加载窗口漏事件。监听创建、修改、移动、移除、子项重排和导入相关事件，合并连续刷新；页面恢复可见、重新连接和写操作失败后再次校准。取消过期读取结果，避免较旧快照覆盖较新界面。没有可靠事件时不能仅依赖常驻后台内存。

写操作按原生 ID 定位，只提交用户修改字段；执行前重新读取相关目标并检查可写性。删除、移动与批量操作需处理目标被其他页面移除的情况。Chrome 不提供通用事务或版本条件写入，产品不承诺跨设备编辑冲突已完全消除。

现有最低 Chrome 版本为 116，新字段通过能力检测使用；缺失 `folderType`/`syncing` 时保守显示并依赖实际 API 校验，不把固定 ID 或本地化名称当唯一依据。根目录不可任意创建/重命名；账户与本地目录可能同时出现。

**地址与隐私边界**

- 读取已有条目时完整保留 URL，不复用旧导入函数的 HTTP-only 过滤而让书签消失。
- 首版新增/修改网址支持 HTTP(S)；现有其他协议条目仍显示原文、可复制与定位到浏览器管理器，默认不从插件执行。`javascript:`、`data:` 等不得执行；不通过自动添加协议改写已有数据。
- 其他协议的完整打开能力待逐类真实浏览器验证后扩展；此限制在条目菜单和帮助中说明。未知/异常网址不自动删除。
- 书签标题、路径、URL 均按不可信文本渲染，复用现有转义与 URL 校验边界；不要插入可执行 HTML。
- 默认使用本地占位 favicon，不因读取完整书签树而批量请求外部服务；用户既有外部图标选项继续遵循现有隐私开关，仅按可见项加载。首版不追加 favicon 或 history 权限。
- 页面说明区分“插件不上传书签”与“浏览器可能按用户设置同步到账户”；前者不能被表述成所有数据永不离开设备。
